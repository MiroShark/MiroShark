# miro_shark

## Project Overview
MiroShark is a Universal Swarm Intelligence Engine that simulates public reaction to documents using hundreds of AI agents with distinct personalities, generating realistic social media interactions and opinion dynamics.

## Tech Stack
- **Backend:** Python 3.11+ / Flask 3.0 / Neo4j 5.15+ / CAMEL-AI (swarm simulation)
- **Frontend:** Vue 3 / Vite / D3.js / Axios
- **Infra:** Docker Compose, Ollama (local LLM), `uv` (Python deps), `npm` (JS deps)
- **LLM:** OpenAI-compatible API (Ollama local, OpenRouter cloud, or Claude Code CLI)

## Architecture
- `backend/app/api/` — Flask route handlers (graph, simulation, report)
- `backend/app/services/` — Business logic (simulation runner, graph builder, ontology, reports)
- `backend/app/storage/` — Neo4j database layer, embeddings, search
- `backend/app/utils/` — LLM client, file parser, retry, logger
- `backend/app/models/` — Pydantic data models
- `frontend/src/views/` — Page-level Vue components
- `frontend/src/components/` — Reusable Vue components (Step1-5 wizard, GraphPanel)
- `frontend/src/api/` — Axios API client wrappers
- `frontend/src/router/` — Vue Router config

## Development Commands
```
# Install all dependencies (npm + Python)
npm run setup:all

# Run development server (backend + frontend concurrently)
npm run dev

# Run backend only
npm run backend

# Run frontend only
npm run frontend

# Build frontend for production
npm run build

# Install Python backend deps only
npm run setup:backend
```

## Project-Specific Rules
- Backend uses `uv` for Python dependency management, not pip
- Frontend dev server runs on port 3001 (3000 is occupied by open-webui)
- LLM calls go through `backend/app/utils/llm_client.py` — never call OpenAI SDK directly
- Neo4j is the only database — no SQL/SQLite

## Secrets Access (VaultSecrets)
Secrets are stored in an encrypted vault on the NAS (192.168.80.14:8100).
To access secrets, use the `vs` command:
```bash
# First time in a session: unlock the vault (opens browser for user to enter password)
vs unlock

# Then fetch any secret by name
vs get SECRET_NAME

# Other commands
vs ls                   # List all available secrets
vs set NAME value       # Add or update a secret
vs rm NAME              # Delete a secret
vs lock                 # Lock the vault (end session)
```
If `vs get` returns "No active vault session", run `vs unlock` first and wait for the user to enter the password in their browser.
